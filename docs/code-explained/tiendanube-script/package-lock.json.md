# `tiendanube-script/package-lock.json`

**HECHO VERIFICADO:** es un lockfile generado por npm; no se comentó ni modificó.

| Propiedad superior | Valor/función |
|---|---|
| `name` | coincide con `package.json`: `setupoficina-tiendanube-cart-bridge` |
| `version` | coincide: `0.1.0` |
| `lockfileVersion` | `3`, formato moderno de npm |
| `requires` | `true`, registra resolución de dependencias |
| `packages` | mapa desde ruta de paquete a metadata resuelta |

La entrada `packages[""]` representa el propio proyecto y repite sus cinco dependencias directas de desarrollo. Las otras **103 entradas `node_modules/...`** registran dependencias directas, transitivas y paquetes binarios opcionales por plataforma.

Campos que aparecen en esas entradas:

| Campo | Propósito |
|---|---|
| `version` | versión exacta resuelta |
| `resolved` | URL del tarball en el registro |
| `integrity` | hash de integridad usado por npm |
| `dev` | marca dependencia de desarrollo |
| `license` | licencia declarada por el paquete |
| `dependencies` / `optionalDependencies` | aristas del árbol transitivo |
| `cpu` / `os` / `optional` | limita binarios opcionales a plataformas concretas |
| `engines` | versiones de runtime declaradas por el paquete |
| `bin` | comandos que expone un paquete cuando corresponde |

**HECHO VERIFICADO:** aparecen variantes de `esbuild` y Rollup para múltiples sistemas operativos; npm elige la aplicable a la máquina. No son código fuente propio del proyecto.

**INFORMACIÓN NO IDENTIFICADA:** el lockfile demuestra la resolución registrada, no que la carpeta local `node_modules` esté intacta o que un build concreto haya usado exactamente esa instalación.
