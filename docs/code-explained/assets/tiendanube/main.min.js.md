# `assets/tiendanube/main.min.js`

## Clasificación

**HECHO VERIFICADO:** es un bundle JavaScript ESM minificado, versionado y generado para el entorno NubeSDK de Tiendanube. No se añadió documentación dentro del archivo porque cualquier rebuild la eliminaría y porque la minificación agrupa código propio con runtime de dependencias.

## Origen comprobado

| Salida | Configuración/fuente |
|---|---|
| `assets/tiendanube/main.min.js` | `tiendanube-script/tsup.config.js` |
| entrada | `tiendanube-script/src/main.tsx` |
| módulos propios incorporados | `src/transfer-core.mjs`, `src/storefront-flow.mjs`, URL resuelta por `build/backend-url.mjs` |
| runtime incorporado | `@tiendanube/nube-sdk-jsx` y dependencias del build |
| formato | ESM, un solo bundle, minificado, sin sourcemap y sin splitting |

`tsup.config.js` inyecta la constante `__SETUPOFICINA_BACKEND_URL__`, configura el alias del runtime JSX y elige `.min.js` como extensión cuando `minify` es verdadero.

## Comportamiento reconocible en la salida

El bundle conserva, con nombres reducidos:

- registro de `App` sobre NubeSDK;
- escucha de `location:updated`;
- lectura de `setupoficina_ticket`;
- POST a `/api/tiendanube/cart-transfer/consume`;
- incorporación secuencial con eventos `cart:add:success`/`cart:add:fail`;
- POST a `/complete`;
- almacenamiento temporal del resultado y navegación a `/cart?setupoficina_result=1`;
- presentación de resultado con slots `corner_top_right` o `modal_content`.

Para aprender o modificar conceptualmente ese flujo deben leerse las fuentes, no intentar reconstruirlo desde los identificadores minificados.

**HECHO VERIFICADO:** `index.html` no referencia este archivo; el frontend de SetupOficina y el storefront de Tiendanube son contextos de ejecución diferentes.

**INFORMACIÓN NO IDENTIFICADA:** el archivo local no demuestra que Tiendanube tenga instalado este build, qué versión estaría activa ni cuándo se habría publicado.
